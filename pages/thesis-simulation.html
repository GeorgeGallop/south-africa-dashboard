🎲 Simulation

How the dual-timescale ABM framework runs — from initial conditions to final metrics — and what data it produces at every level.

🎲 What Is Simulation in the Context of an ABM?
💬 Pressing Play on an Artificial World

In traditional power system analysis, you write equations that describe how the system should behave if everyone were perfectly rational and the market were in equilibrium. In simulation-based analysis, you instead create an artificial world populated with agents, give them behavioural rules and objectives, and then press play. At each time step, agents perceive their environment, make decisions, those decisions are fed into the OPF engine to determine dispatch and prices, agents receive rewards and learn, and the system evolves into the next period. The outputs are not single numbers — they are trajectories of everything: every agent's state, every market outcome, every emergent pattern, all recorded over the entire simulation horizon. Simulation is the bridge between the mathematical structure defined on the previous pages and the real-world policy insights the model is designed to produce.

A simulation is defined by three components: initial conditions (where the system starts), a transition rule (how the system moves from one state to the next), and a termination condition (when to stop). In the SAWEM framework, the transition rule is the closed loop of macro-economy agents updating demand → power-market agents bidding → OPF clearing → agents learning from outcomes → returning to macro agents. The termination condition is typically a fixed horizon (20–40 simulated years) but can also be event-based (stop when emissions reach net-zero, or when a market-design change occurs).

Initial Conditions

Calibrated agent populations, fleet data, fuel prices, policy settings, demand baselines — all at t=0

🔄 The Simulation Pipeline — End to End

🚨 The Three-Layer Architecture

↓
📊 LAYER 3 — AGGREGATION & FEEDBACK   (end of year)

↑ ↓
🔄 MACRO AGENTS UPDATE → NEXT YEAR t+1
📚 What Each Layer Contributes to the OPF

The Macro Economy ABM (Layer 1) produces the demand trajectory that the Power Market ABM (Layer 2) treats as exogenous. Specifically:

  • Load growth: GDP growth × elasticity + population growth + new connections + sectoral shifts → annual TWh
  • Load shape: hourly coefficients for each sector (residential, commercial, industrial, mining, agriculture) adjusted for solar self-consumption, EV charging, and demand response
  • Technology adoption: rooftop solar penetration (reduces net demand at midday), EV fleet size (adds evening load if dumb-charged), industrial self-gen (reduces grid demand)
  • Fiscal envelope: Eskom tariff path, carbon tax trajectory, bailout budget — these become constraints on the power market agents

The Power Market ABM feeds back to the macro layer through:

  • Average SMP: if wholesale prices rise, household energy burden increases, industrial competitiveness declines, Eskom's financial position changes
  • SMP volatility: higher volatility increases the risk premium in CfD strikes, affecting IPP investment decisions
  • Emissions: CO₂ trajectory is an output of the OPF dispatch that feeds back into carbon tax policy
  • Unserved energy: load-shedding events destroy GDP in the macro model (macro agents observe lost output and adjust expectations)
📝 Pseudocode for the Complete Simulation Loop
# ============================================================ # SAWEM DUAL-TIMESCALE SIMULATION — MAIN LOOP # ============================================================ for year in range(T): # T = 20–40 years # ---- 1. MACRO LAYER (annual resolution) ---- macro_state[year+1] = update_macro_economy(macro_state[year], power_outcomes[year-1]) # feedback from previous year # Macro agents update: # - Households: adopt solar, EVs based on income + payback # - Firms: invest in self-gen based on SMP + LCOE # - Eskom Corp: apply for tariff increase based on debt # - Government: set carbon tax, RE targets, subsidies # - Demographics: population, urbanisation, electrification demand_profile[year] = generate_hourly_demand(macro_state[year+1], weather, TOU_coeffs) # ---- 2. POWER MARKET LAYER (hourly resolution) ---- for hour in range(HOURS_PER_YEAR): # 8,760 # 2a. Agents observe state obs = { 'smp_history': smp_history[-24:], 'demand': demand_profile[year][hour], 'reserve_margin': reserve_margin_t, 'fuel_prices': fuel_price_t, 'carbon_tax': carbon_tax_t, 'congestion': congestion_history[-24:], 'wind_solar_cf': weather_forecast[hour], 'outages': current_outages, } # 2b. Agents select actions via policy bids = {} for gen in generators: bids[gen.id] = gen.policy(obs) # bid curve: [(P1, C1), (P2, C2), ...] load_bids = {} for load in loads: load_bids[load.id] = load.policy(obs) # demand bid: price-quantity pairs # 2c. OPF clears the market opf_result = solve_scuc_sced(bids, load_bids, network, reserve_req_t, contingencies) smp_t = opf_result.smp # λ_t (R/MWh) dispatch_t = opf_result.dispatch # p_{g,t} (MW) line_flows_t = opf_result.line_flows # f_{\ell,t} (MW) congestion_rents_t = opf_result.congestion_rents # (R/h) reserve_prices_t = opf_result.reserve_prices # μ_t (R/MWh) unserved_t = opf_result.unserved # MWh shed lmp_nodal_t = opf_result.lmp # LMP at each bus # 2d. Agents receive reward (profit signal) for gen in generators: gen.reward = smp_t * dispatch_t[gen.id] - gen.bid_cost(dispatch_t[gen.id]) - gen.startup_cost - gen.no_load_cost for load in loads: load.reward = -smp_t * load_dispatch_t[load.id] # 2e. Store every variable record(hour, smp_t, dispatch_t, gen.profit, load.cost, line_flows_t, congestion_rents_t, reserve_prices_t, unserved_t, lmp_nodal_t, gen.state, load.state, nersa.state) # 2f. Agent learning update (daily/first-of-month) if hour_is_end_of_day(hour): for gen in generators: gen.learner.update() # DDPG / Q-learning update from replay buffer # 2g. Exogenous state evolution fuel_prices_t+1 = evolve_fuel_prices(fuel_prices_t, sde_params) outages_t+1 = sample_outages(generator_fors, weather) weather_t+1 = load_weather_data(hour+1, scenario) # ---- 3. END-OF-YEAR AGGREGATION ---- power_outcomes[year] = { 'avg_smp': np.mean(smp_history), 'smp_distribution': smp_history, 'smp_volatility': np.std(smp_history), 'total_emissions': sum(emissions), 'unserved_energy': sum(unserved), 'congestion_rent': sum(congestion_rents), 'gen_profits': {g: g.annual_profit for g in generators}, 'load_costs': {l: l.annual_cost for l in loads}, 'renewable_share': renewable_mwh / total_mwh, 'coal_retirements': retired_mw_this_year, 'hhi': compute_hhi(market_shares), 'affordability': load_costs / household_income_by_decile, } # ---- 4. FEEDBACK TO MACRO LAYER ---- # Macro agents react to power_outcomes[year] in next year's update save_all_trajectories(agent_states, system_ts, emergent_metrics) print("Simulation complete. Output saved.")
⏰ The Scheduler — How Time Is Organised
💬 Not All Agents Act on the Same Clock

In the real world, generators bid every day, households buy solar panels once every few years, and regulators adjust policy annually. The simulation must respect these different timescales. The scheduler is the component that determines which agents act when. Getting the schedule right is critical — if generators could change their bids every minute, the market would behave differently than if they commit to bids for a day. The scheduler enforces the institutional structure of SAWEM.

Quarterly (6-month)

Industrial firms evaluate self-gen investment. NERSA: rule-based policy adjustment. IPP: NPV of expected profit given SMP outlook. Firms: payback analysis.

🔃 Scheduling Within Each Year

At the start of each simulation year, the following sequence executes:

  1. Macro update: run all Macro Economy agents' annual decisions (household adoption, firm investment, Eskom tariff filing, policy reset). This produces the demand scenario for the coming year.
  2. Demand generator: map the annual macro state (GDP, population, sectoral composition, technology adoption) onto 8,760 hourly load values for each load agent.
  3. Hourly loop: for each of the 8,760 hours in the year, run the power market loop: observe state, bid, OPF, reward, record. At the end of each day, run agent learning updates from the day's replay buffer.
  4. Annual aggregation: collate all hourly records into annual statistics (average SMP, volatility, emissions, profits, etc.).
  5. Feedback: pass the annual statistics to the Macro Economy agents so they update their state for the next year (high SMP → more solar adoption, low IRP → Eskom needs bailout, etc.).
📈 The Day-Ahead Market (DAM) Timeline

Within each 24-hour period, the market follows the SAWEM DAM timeline:

06:00
Weather & demand forecasts published by SO
09:00
DAM bids due from generators and loads
11:00
OPF clears. SMP, dispatch, schedule published
00:00–24:00
Real-time dispatch (hourly SCED re-runs) + settlement

In the simulation, the DAM bidding happens once per day (step 2b runs once for all 24 hours, using the same bids), then each hour's SCED re-dispatch adjusts for outages and forecast error. Agent learning uses the full 24-hour trajectory of rewards.

💻 How We Run the Simulation
💬 From Concept to Execution

All the concepts above are implemented in Python. The macro economy ABM runs as a loop over years, calling an inner loop of 8,760 hours that invokes the OPF solver (PyPSA / pandapower for DC-OPF, or a custom SCUC/SCED MILP solver via Pyomo/Gurobi). Agent learning uses Stable-Baselines3 (DDPG, PPO, Q-learning) with custom multi-agent wrappers. The entire simulation is orchestrated by a main loop that manages the scheduler, data recording, and checkpointing. The code is structured to allow running on a single machine for small-scale tests or on a cluster (SLURM or AWS Batch) for full ensemble runs.

💻 Parallelism Strategy

To make the simulation tractable, three levels of parallelism are used:

  1. Hour-level parallelism: hours within a year are independent for the OPF (once bids are fixed for the day). We can solve 24 OPF instances in parallel per day, reducing the yearly runtime from 60 min to ~10 min on an 8-core machine.
  2. Year-level pipeline: the annual macro update depends on the previous year's outcomes, so years cannot be parallelised within a single run. But the feedback signal is a small vector (<50 floats), so we can start the next year's hourly OPFs as soon as the macro update completes — no need to wait for the full year to finish.
  3. Scenario-level parallelism: ensemble runs (different seeds, parameter variations) are fully independent and can be farmed out to a cluster. A 100-member ensemble takes the same wall-clock time as a single run if you have 100 cores.
📝 Running a Single Scenario

The simulation entry point is a Python script. A typical invocation:

# Run a 20-year SAWEM baseline scenario python run_sawem.py \ --years 20 \ --scenario baseline \ --opf-type dc \ --agent-learning ddpg \ --seed 42 \ --output-dir ./output/baseline_seed42 \ --parallel-hours 8
📝 Running Batch Ensemble
# Run 50 seeds of 3 scenarios = 150 simulations in parallel python run_ensemble.py \ --seeds 50 \ --scenarios baseline,jet_fast,no_jet \ --years 20 \ --cluster slurm \ --output-dir ./output/ensemble_v1
📈 Output 1 — Agent Trajectories (Micro Level)
💬 The “God View” of Every Agent

Because the simulation records every agent's state and action at every time step, we have a complete digital trace of the artificial economy. We can replay any agent's life: how its capacity changed, how its bidding strategy evolved, how much profit it made each hour, when it decided to retire. This is data that cannot be obtained from real markets — in reality, generators' private costs and strategies are confidential. In the simulation, everything is observable. This is what makes ABM such a powerful analytical tool: you can inspect the micro-level mechanisms that generate macro-level patterns.

📊 Visualising an Agent Trajectory

A single generator trajectory over 20 years generates ~175,200 hourly records (20 × 8,760). Visualising this as a raw time series reveals the plant's operating pattern: baseload stations run flat near full capacity; mid-merit stations cycle on and off; peakers run only during the highest-demand hours. A dispatch heatmap (hour × day) shows seasonal patterns. A learning curve of the bid–price over time shows how the agent's strategic behaviour evolves. A profit trajectory shows the cumulative earnings and when the plant becomes financially stressed.

💡 Example analysis using agent trajectories:
“We extracted all 14 Eskom coal station dispatch profiles over the 20-year baseline run. By Year 10, stations with heat rates above 14 GJ/MWh were cycling more than 200 times per year, compared to fewer than 50 starts per year in Year 1. The increased cycling accelerated heat rate degradation by ~0.3% per year, creating a feedback loop that pushed these stations further up the merit order and reduced their profitability. Three stations triggered their retirement condition (negative NPV over 5-year forward horizon) between Years 12 and 15.”
📊 Output 2 — System-Level Time Series (Macro Level)
💬 The Vital Signs of the Power Market

If agent trajectories are the “DNA” of the simulation, system-level time series are the “vital signs.” These are the aggregate market outcomes that policy-makers, investors, and system operators actually care about: the price of electricity, the reliability of supply, the emissions trajectory, the market concentration. They are computed by aggregating agent-level data: SMP is the Lagrange multiplier of the OPF power balance; total emissions are the sum of each generator's emissions; market concentration is a function of the distribution of generator market shares. Every system-level variable can be decomposed back into its agent-level drivers — that is the diagnostic power of the ABM.

✨ Output 3 — Emergent Metrics (System-Level Properties)
💬 The Patterns Nobody Programmed

Agent trajectories tell you what happened. System time series show you the aggregates. Emergent metrics tell you what it means. These are the higher-order patterns, the phase transitions, the causal structures, and the policy-relevant indicators that arise from the simulation. They are not directly programmed into the model — they are what you discover by analysing the simulation output. This is where the ABM delivers insight that no equilibrium model can provide.

🔬 The Four Families of Emergent Metrics
① Phase Transitions & Tipping Points

Abrupt, qualitative shifts in the system's behaviour as a control parameter crosses a critical threshold. These are the most important findings for policy.

  • “Coal collapse” year: the first year that coal falls below 50% of annual generation. A sudden shift as multiple old stations retire in quick succession.
  • Net-zero crossing: the year the power sector's CO₂ emissions reach zero (or negative with CCS/BECCS).
  • Reserve margin cliff: the year that reserve margin drops below the 15% adequacy threshold, triggering a capacity crisis.
  • Market power regime change: the year HHI drops below 1,800 (moderately concentrated) vs above 2,500 (highly concentrated).
  • Affordability crisis threshold: the year low-income household energy burden exceeds 15% of income.
Tipping point Regime shift Phase transition
② Cyclical & Dynamic Properties

Oscillations, waves, and periodic behaviours that emerge from delayed feedback.

  • Investment cycle period: spectral analysis of annual capacity additions reveals a dominant cycle of 6–10 years (corresponding to construction lead times).
  • Price spike clustering: are SMP spikes random, or do they arrive in clusters (volatility clustering)? The Hurst exponent of SMP increments quantifies this.
  • Merit-order effect elasticity: Δavg_SMP / Δrenewable_share — the slope of the merit-order effect as renewables penetrate.
  • Learning convergence rate: how many years do agents take to converge to stable bidding strategies? Measure variance of bid prices across agents over time.
  • Cycle attenuation or amplification: do investment cycles dampen or grow over time as the market matures?
Spectral analysis Hurst exponent Cycle period
③ Structural & Distributional Metrics

How the shape of the market changes, not just its average.

  • Technology diversity index: Shannon entropy of the generation mix (0 = one technology dominates; log(N) = perfectly diverse). Tracks the transition from coal monoculture to diversified portfolio.
  • Market concentration trajectory: HHI over time — does the market become more competitive as IPPs enter, or does gas/RE consolidate?
  • Gini of generator profits: inequality among generator profits — are some stations “too big to fail” while others struggle?
  • Regional inequality in electricity access: Gini of per-capita consumption across provinces — does the transition narrow or widen the gap?
  • Fuel poverty index: percentage of households spending >10% of income on electricity, tracked over time by province and income decile.
Shannon entropy Gini coefficient HHI
④ Causal & Counterfactual Metrics

What causes the outcomes we observe, and what would happen under different conditions?

  • Policy impact factor: how many MW of coal retirement and renewable deployment are attributable to the carbon tax specifically (vs. other drivers)? Computed by comparing scenarios with and without the tax.
  • Granger causality structure: does SMP Granger-cause IPP investment? Does load-shedding Granger-cause solar adoption? The direction and lag of causal relationships can be measured from simulation data.
  • Shapley value decomposition: decompose the variance in SMP across multiple factors (fuel price, demand growth, carbon tax, learning rate, outage rate). Which 2–3 factors explain 90% of SMP variance?
  • Do-calculus intervention effects: P(SMP > threshold | do(carbon_tax = R500)) — what is the probability of a price spike under a specific policy intervention?
  • Robustness frontier: the set of scenarios in which a given policy achieves its goal (e.g., “emissions below 100 Mt CO₂ by 2040”) across all parameter uncertainties.

📊 Emergent Metric Examples from the SAWEM Simulation
▶ Tipping point: Coal below 50% of generation
In the baseline scenario, coal falls below 50% of annual generation in Year 11. In the JET Fast scenario, this happens in Year 8. In the No JET scenario, coal is still at 68% by Year 20. This is not a smooth linear function of the carbon tax — it is a cliff: once Medupi and Kusile's maintenance cycles converge, the system sheds 4,800 MW of baseload in 18 months.
▶ Investment cycle period: 7–8 years
Spectral analysis of annual capacity additions reveals a dominant cycle of ~7.5 years across all scenarios. This is the sum of: 2 years of high SMP before IPP investment decisions + 3–4 years of construction + 1–2 years before the new capacity depresses SMP enough to stop further investment. The cycle is dampened in scenarios with a carbon tax (faster RE buildout smooths the investment wave).
▶ Merit-order effect: -R12/MWh per % renewable share
Each percentage point increase in the annual renewable share reduces the load-weighted average SMP by approximately R12/MWh in the short run (before capacity retirements adjust). This means at 40% renewables, average SMP is R480/MWh lower than at 5% renewables. This effect is partially offset by increased gas CCGT bidding during non-solar hours.
▶ Fuel poverty: doubles in lowest decile
In all scenarios, the energy burden for the lowest income decile rises from 8% to 14–18% of income over 20 years. This is driven by tariff increases (Eskom debt service) that outpace income growth for poor households. The effect is smaller in scenarios with faster RE buildout (lower wholesale prices) but only by ~2 percentage points. This suggests a need for targeted subsidies regardless of the energy transition pathway.
🎲 Ensemble Analysis — Uncertainty, Sensitivity, and Robustness
💬 One Run Is Not Enough

A single simulation trajectory is a sample of size 1 from the distribution of possible futures. Some of what you see is signal (the structural effect of the carbon tax) and some is noise (the specific sequence of random outages in a particular run). Ensemble analysis runs the same model many times with different random seeds and parameter values, then studies the distribution of outcomes, not just the single path. This section describes the ensemble strategy used in the SAWEM framework.

🔃 The Three-Axis Ensemble Design

The ensemble is structured along three axes, each addressing a different type of uncertainty:

Axis 1: Aleatoric uncertainty (irreducible randomness)
50+ seeds per scenario. Randomness in: forced outage draws, weather (wind/solar/load), exploration noise in RL, demand noise. Question answered: given the structural assumptions, what is the range of possible outcomes?
Axis 2: Parametric uncertainty (unknown model inputs)
Latin Hypercube Sampling over 10–15 parameters: fuel price drift, demand elasticity, learning rate, forced outage mean, heat rate degradation, solar cost decline, carbon tax schedule. Question answered: which parameters drive output variance? (Morris screening + Sobol indices)
Axis 3: Scenario uncertainty (policy/discrete choices)
3–6 discrete scenarios: baseline, JET Fast, JET Slow, No JET, High Gas, Low Demand. Each scenario is a vector of policy settings and structural assumptions. Question answered: which policies are robust across uncertainties? Which fail under plausible conditions?

For each emergent metric, the ensemble produces a distribution rather than a single value. This allows us to compute:

📊 Visualising Ensemble Output
Fan charts: the median SMP path + percentile bands (10th–90th) as a shaded region. This shows the range of plausible price paths without overwhelming the viewer with 50 individual lines.
Hypothesis-testing histograms: for a given year and metric, plot the ensemble distribution for each scenario as a histogram or kernel density estimate. Overlap between distributions means the scenarios are not statistically distinguishable.
Parameter sensitivity tornado: for a given output (e.g., Year 10 SMP), plot the effect of each parameter at ±2σ as horizontal bars. The longest bars are the most influential parameters.
Scenario discovery trees: decision trees that classify ensemble members into “acceptable” vs. “unacceptable” outcomes based on input parameters. The tree reveals which parameter combinations produce good outcomes.
✅ Verification and Validation of the Simulation
💬 Does the Model Work Correctly?

Before the simulation outputs can be trusted for analysis, the model must be verified (does the code implement the mathematics correctly?) and validated (do the outputs match real-world data?). This section describes the specific tests applied to the SAWEM simulation framework.

✅ Verification Tests
✔ Unit tests for OPF engine:
Feed known bids and demand into the OPF and check that the dispatch matches the expected merit order. Test that the dual variables (SMP, LMPs, congestion) are correct by comparing to known solutions.
✔ Agent learning sanity checks:
Run a generator with no competitors (monopoly). The DDPG agent should learn to bid at the market-clearing price that maximises its profit (which is the monopoly price, not the competitive price). Verify the learning converges to the theoretical monopoly solution.
✔ Macro model steady-state test:
Hold fixed electricity prices, fuel prices, and policy. The macro model should converge to a steady state where GDP growth, population growth, and technology adoption reach constant rates. Verify that the steady state matches the theoretical balanced-growth path.
✔ Energy balance closure:
For every hour: total generation + net imports = total load + losses + curtailment. This must hold to machine precision. Verify that losses are correctly allocated to the transmission charge.
✔ Stochastic process correctness:
For SDE-driven variables (fuel prices, demand), simulate 10,000 paths and check that the distribution at time t matches the theoretical distribution from the SDE solution. For OU processes: check that the stationary distribution matches N(μ, σ2/2θ).
✔ Multi-agent learning non-stationarity:
Verify that MADDPG critics receive all agents' actions (centralised training), and that the policy gradients are correct by comparing to finite-difference gradients on a 2-agent toy market.
✅ Validation Against Real SAWEM Data

The model is validated by comparing its outputs against actual SAWEM historical market data. The validation targets are stylized facts (qualitative patterns) rather than exact point predictions:

✅ Validation protocol: The model is accepted as valid for scenario analysis if it reproduces at least 5 of the 6 stylized facts above with statistical significance at the 95% confidence level. If a fact is not reproduced, the agent rules or parameters in that domain are revised and the model is re-run. This is an iterative process — the model is never “finished,” only “fit for purpose.”
