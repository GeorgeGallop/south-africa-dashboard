💱 Currency — ZAR crosses and history windows

Cross Spot Day 1W 1M 3M 6M 1Y 1Y range 1Y trend

Returns are computed from daily closes in ZAR per unit of foreign currency, so a positive figure means the rand weakened against that currency. The range column shows where today sits between the 52-week low and high.

🌍 Equal-weighted ZAR vs majors (derived)

Derived here, not a published benchmark: each cross is rebased to 100 at the start of the window, averaged, then inverted so a rising line means a stronger rand.

📐 Reading the windows
  • 1W — positioning and event risk around data prints.
  • 1M — the market's current narrative on the rand.
  • 3M / 6M — the medium-term trend that feeds import and input-cost assumptions.
  • 1Y — the cycle: what a rand hedge has actually returned over twelve months.

📚 Sources & methodology
  • Equities — every price, session change and market cap is fetched live from Yahoo Finance's JSE feeds by the dashboard's own server (/api/market/equities). The figures are cached on disk for 15 minutes, and a cached fetch is only reused while it belongs to the current JSE session: once a new session opens, the cache is refetched even if it is only minutes old, so a reload after the close shows that close rather than the previous day's. Market caps are the provider's own figures, in rand.
  • Finding the API — the pages are usually opened from a static server (Live Server, or file://), where this origin has no /api/market/*. The page therefore looks for the dashboard server at this origin first, then at http://localhost:3101, and uses whichever answers. The same lookup serves the headline strip's /api/rss proxy. Start the server with py server.py.
  • Stored snapshot fallback — only when no API answers anywhere does the page fall back to data/market-snapshot.js, a stored capture of the same series at its last settled close. The header source line, the amber notice above and the age next to each figure all say so, so a stored close is never shown as a live price. Its .json sibling is re-read on load whenever the script copy is from an earlier session, so regenerating with py -m market.snapshot is enough — no hard reload needed.
  • Session basis — outside JSE hours (09:00–17:00 SAST, Monday–Friday) the price is the settled last close. During the session the header says live session (intraday) and the change is measured against the previous close.
  • Coverage — a curated universe of JSE listings with SA exposure across the ICB industry sectors (Technology, Telecommunications, Health Care, Financials, Real Estate, Consumer Discretionary, Consumer Staples, Industrials, Basic Materials, Energy, Utilities). A sector with no priced member is omitted rather than shown empty. Codes the free feed does not carry appear in the coverage note instead of being shown with a stale price.
  • Currency — /api/market/fx returns ZAR crosses with 1W–1Y windows computed from one year of daily closes. The equal-weighted ZAR index is derived by this dashboard and is labelled as such; it is not a published benchmark.
  • Bonds — /api/market/bonds returns the SA sovereign curve, the same benchmarks against the SARB policy rate, the annual curve history, sovereign ratings and the 5-year CDS, sourced from World Government Bonds' JSE-derived daily benchmark yields.
  • Freshness — the source line under the header names the session each series belongs to, the provider that supplied it, and how long ago it was captured. A reload always ends up on the current session's figures: if the API hands back an earlier session's close, the page re-requests it with a forced refresh before rendering anything. Refresh all bypasses the cache outright, and retries the live API when the page is running on the stored snapshot.
  • Market analysis only — not investment advice.
